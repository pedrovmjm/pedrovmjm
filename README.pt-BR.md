## As três personalidades do meu nome

Meu nome é grande o suficiente para parecer uma squad inteira.  
Então eu aceitei que cada parte dele virou uma personalidade no desenvolvimento de software.

### 🟢 Pedro

O Pedro é o cara correto.

Ele pensa em arquitetura, testes, observabilidade, logs padronizados, segurança, documentação, CI/CD, versionamento, governança e tudo aquilo que faz um sistema sobreviver depois da primeira sprint.

É o Pedro que abre o pull request com calma, escreve descrição, coloca contexto, pensa nos casos de borda e ainda pergunta:

> “Isso está escalável? Está seguro? Está observável?”

O Pedro é o lado que tenta fazer tudo certo desde o começo.

### 🟡 Marcelino

O Marcelino acredita no Go Horse.

Ele sabe que existe débito técnico.  
Ele sabe que aquela decisão vai cobrar juros.  
Ele sabe que o design pattern poderia estar melhor.  
Ele sabe que talvez aquele `TODO` nunca mais seja visto.

Mas ele olha para o prazo, olha para o backlog, olha para a squad e diz:

> “Depois a gente refatora.”

Marcelino entrega.  
Às vezes bonito.  
Às vezes funcionando.  
Mas entrega.

Ele não odeia boas práticas.  
Ele só acha que, em alguns momentos, o deploy também tem sentimentos.

### 🔴 Victor

O Victor é o caos controlado.

Se precisar arrumar algo urgente, ele arruma.  
Se precisar investigar um bug estranho, ele entra.  
Se precisar entender por que produção está se comportando como se tivesse consciência própria, ele encara.

O Victor não tem medo do incidente.  
O Victor tem medo é de reunião sem objetivo.

Ele fala pouco, olha logs demais, mantém o Grafana aberto e, se precisar derrubar algo em horário comercial para salvar o dia... ele não está dizendo que faria, mas também não está dizendo que não faria.

> “Produção caiu? Agora é comigo.”
